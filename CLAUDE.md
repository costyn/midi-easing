# MIDI Easing Proxy - Claude Instructions

## Project Context

This is a C++ application that acts as a MIDI proxy between an Akai MidiMix controller and Modulaser software, providing smooth easing transitions and intelligent pickup/latch behavior to prevent jarring value jumps during preset changes.

## Tech Stack

- **Language**: C++17
- **Build System**: Makefile (not CMake/Meson)
- **MIDI Library**: RtMidi 6.0.0 (CoreMIDI backend for macOS)
- **Easing Library**: AHEasing (Robert Penner's easing equations)
- **Platform**: macOS only (uses CoreMIDI framework)

## Architecture

### Core Components

1. **[midi-easing-proxy.cpp](midi-easing-proxy.cpp)**: Main application
   - MIDI I/O handling (RtMidi)
   - Easing engine (100Hz thread)
   - Latch/pickup logic
   - Configuration loading
   - Device polling thread

2. **[led_controller.cpp](led_controller.cpp)** / [led_controller.h](led_controller.h): LED feedback system
   - Startup light show sequences
   - Dynamic LED control from Modulaser messages
   - Note-to-LED mapping for MidiMix

3. **[test-midi-proxy.cpp](test-midi-proxy.cpp)**: Unit test suite
   - Tests for configuration parsing
   - Easing threshold logic validation
   - State management verification

4. **[test-leds.cpp](test-leds.cpp)**: LED testing utility
   - Interactive LED testing
   - Note scanning tool

### Threading Model

- **Main Thread**: Setup, device polling, console output
- **RtMidi Callback Threads**: MIDI message handling (audio priority)
- **Easing Thread**: 100Hz calculations and output
- **Polling Thread**: Device detection every 1 second

All shared state protected by mutex.

### Key Data Structures

**ControlState** (per CC 0-127):
- `last_hardware_value`: Last value from MidiMix
- `last_modulaser_value`: Last value from Modulaser echo
- `target_value`: Easing target
- `easing_start_time`: When easing began
- `easing_duration`: Duration in milliseconds
- `is_easing`: Whether actively easing
- `is_latched`: Whether waiting for pickup

## Configuration System

### [config.ini](config.ini) Structure

```ini
[MIDI]
input_port_name = MIDI Mix
virtual_port_name = Midi Easing

[Settings]
whitelist_controls = 61,62        # Bypass easing
easing_threshold = 3              # Min change to trigger easing
update_rate_hz = 100              # Easing thread frequency

[DEFAULTS]
default_easing_duration = 5000    # Default duration (ms)

[Easing_durations]
18 = 3000                         # Per-control overrides
19 = 1500
```

### Special Control Transformations

**CC61**: Maps 0-127 → 0-31 (speed range reduction)
**CC62**: Inverts value (127 - value) for crossfader orientation

These controls bypass ALL easing and are processed immediately.

## Important Implementation Details

### Latch/Pickup System

The core feature that prevents jumps:

1. **Latching**: When hardware value ≠ software value (detected via echo), control enters latched state
2. **Pickup Detection**: Hardware must move through software value (within threshold) to unlatch
3. **Resume**: After pickup, normal easing behavior resumes

This is critical for live performance usability.

### Echo Message Handling

- Modulaser echoes MIDI messages back to proxy
- Proxy tracks these to maintain software state
- CC61/CC62 echoes are ignored (transformation controls)
- Essential for latch/pickup logic

### Thread Safety

- All `ControlState` access protected by `stateMutex`
- Callback threads must acquire mutex before state changes
- Easing thread acquires mutex for read/write operations

## Common Tasks

### Adding a New Control Transformation

1. Update transformation logic in `midi-easing-proxy.cpp` callback
2. Add to whitelist if it needs immediate response
3. Update README.md with reasoning

### Changing Easing Function

1. Modify easing calculation in easing thread
2. AHEasing provides: Linear, Quadratic, Cubic, Sine, Exponential, etc.
3. Test with different parameter types (slow/fast changing)

### Adding LED Patterns

1. Modify [led_controller.cpp](led_controller.cpp)
2. Use `sendNoteOn(note, velocity)` and `sendNoteOff(note)`
3. Test with `test-leds` utility first

### Debugging MIDI Issues

1. Run without `-q` flag to see all messages
2. Verify Modulaser is echoing messages
3. Check latch state in verbose output
4. Use macOS Audio MIDI Setup.app to verify ports
